download only keeps the corpus growing — acquisition and discovery carry on — while the CPU-heavy stages (parse, index, embed) stand down. The two halves cost very differently: moving bytes is nearly free, while rdf/fts/embed run every core hot. Per-collection embed modes are left untouched, so switching back to run everything restores exactly what each collection was doing. pause stops all of it, including starting new fetches. One node-wide setting, not per-collection.
Document counts are cached for two minutes and refreshed in the background — the numbers below are {% if counts_age < 5 %}fresh{% else %}up to {{ '%.0f'|format(counts_age) }}s old{% endif %}. Each one is a full scan of that collection's documents table (24M rows for pubmed, ~12s), so computing them per page load made this page a 20-second wait. A backfill moves over days; a two-minute-old count does not mislead, but a count of unknown age would.
